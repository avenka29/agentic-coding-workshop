# Agent instructions

## Project and architecture
This is a minimal starter for a 30-minute agentic coding workshop: 10 minutes of concepts and 20 minutes of hands-on work. React + TypeScript + Vite in `frontend/` calls FastAPI in `backend/` through Vite's `/api` proxy. SQLite is local; `backend/app.py` owns the schema and seeds three tasks on first startup. Existing operations are list, toggle completion, and delete. **Task creation is deliberately absent; implement it only when assigned a workshop ticket.**

## Commands (from repository root)
Convenience commands: `bash scripts/setup.sh` installs dependencies and runs checks; `bash scripts/dev.sh` runs both services and stops them together on Ctrl-C.

Prerequisites: Node.js 22 LTS with npm; Python 3.11–3.13 with venv/pip; Git. Install before the timed exercise.

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm --prefix frontend install
(cd backend && .venv/bin/python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000)
# Separate terminal:
npm --prefix frontend run dev
# Verification:
(cd backend && .venv/bin/python -m pytest -q)
npm --prefix frontend test
npm --prefix frontend run build
```
Open http://127.0.0.1:5173. FastAPI docs: http://127.0.0.1:8000/docs. No external services or API keys are needed. Set `TASKS_DB` to an absolute SQLite path to override the default per-checkout database.

## Ownership and conventions
- Frontend agent: edit only `frontend/` (including its tests). Read `docs/frontend-ticket.md`.
- Backend agent: edit only `backend/` (including its tests). Read `docs/backend-ticket.md`.
- Read shared docs; do not edit root instructions, shared docs, or the other agent's directory for this exercise. Ask the facilitator if a shared change is essential.
- Keep React components and typed API helpers straightforward. Use accessible labels, explicit loading/error states, and existing CSS. Avoid new dependencies.
- Use Python type hints, Pydantic validation, parameterized SQL, and existing connection transactions. Retain `create_app(db_path)` for isolated tests.
- Keep changes narrowly scoped. Do not refactor unrelated code or introduce infrastructure.

## API contract
Existing routes: `GET /api/tasks` → 200 array of tasks, `PATCH /api/tasks/{id}` with `{"completed":true}` → 200 updated task, `DELETE /api/tasks/{id}` → 204 empty response. Missing IDs return 404; invalid completion payloads return 422.

Workshop feature: **POST `/api/tasks` (not present in starter)**.
Request: `{"title":"Finish homework","description":"Complete physics assignment"}`.
Success: HTTP 201, `{"id":1,"title":"Finish homework","description":"Complete physics assignment","completed":false}` (ID generated by SQLite).
- `title` must be a string; required and nonblank after trimming whitespace. Store the trimmed title.
- `description` is an optional string; omitted means `""`. Preserve supplied text. Null and non-string values are invalid.
- Server always creates `completed: false`; callers do not control IDs or completion.
- Invalid requests return HTTP 422 with FastAPI's standard `detail` validation response. Frontend may show a friendly generic validation message; it need not parse every detail.
- Use relative `/api/tasks` URLs. No cross-origin setup or shared generated client is required.

## Worktrees and verification
Start both branches from the same clean committed starter. Each agent works in its assigned worktree and branch. Install dependencies separately in each checkout: worktrees share Git history, not node_modules, virtualenvs, or SQLite files. Do not copy virtualenvs: recreate them. Default ports are shared across the machine; stop the starter services before running another checkout on those ports, or choose alternate ports and adjust only that checkout's Vite proxy if needed. The simplest exercise uses one running app in the integration checkout.

Before committing, run the checks for your directory, review `git diff --check` and `git diff`, and confirm `git status` shows only owned files. Backend tests must use temporary databases, never the participant database. Add creation tests in the backend ticket; the starter's absence check is a manual preflight, so no obsolete test needs to be removed. Commit only your ticket's files with a descriptive message. Integration owner merges both branches, runs all tests/build, and verifies creation in the browser plus persistence after restarting the backend.

Avoid destructive commands (`git reset --hard`, `git clean -fd`, force pushes, deleting worktrees with unfinished work). Never commit secrets, `.env`, dependencies, build outputs, or databases. Do not push without explicit approval. `CLAUDE.md` must remain a symbolic link to this file.
